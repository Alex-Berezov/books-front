# /gates - обязательные проверки

Аргументы: $ARGUMENTS

## Что запускать

Без аргументов:

```
node .claude/hooks/gates.js
```

Скрипт сам берёт список гейтов из `.claude/hooks/rules.json`, отбирает нужные по изменённым
файлам (`when: always` или `when: glob:<шаблон>`), запускает их и печатает вывод. Код возврата 1,
если упал хотя бы один гейт.

`/gates --list` - показать, что будет запущено, и ничего не запускать:

```
node .claude/hooks/gates.js --list
```

`/gates --only=typecheck,lint` - прогнать только названные гейты:

```
node .claude/hooks/gates.js --only=typecheck,lint
```

Идентификаторы бери из `rules.json` или из вывода `--list`. Неизвестный id скрипт назовёт сам.
Есть ещё `--bail` - остановиться на первом падении; передавай его, когда человек попросил быстрый
ответ «зелено или нет».

## Как отвечать

Приведи **фактический вывод команды**: строки, которые она напечатала, и её код возврата.

Запрещено пересказывать результат словами вместо вывода. Строки «все проверки прошли»,
«линт чистый», «typecheck зелёный» без самого вывода не принимаются - ни при успехе, ни при
падении. Вывод длинный - скрипт уже режет его сам; сокращать сверх этого нельзя.

Отдельно про фронт: `yarn validate` за проверку не считается - он завершается успехом при красном
линте. Гейт называется `lint`, и смотреть надо его вывод.

Про `lint` в бэкенде: он правит файлы на месте. После него перечитай изменённые файлы, прежде чем
продолжать правки, иначе затрёшь исправления форматтера.

Гейт упал - назови упавший id, приведи его вывод и остановись. Чинить в этом же ходу начинай
только тогда, когда причина очевидна из вывода и правка укладывается в одну строку.
